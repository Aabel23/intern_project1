## RAM state ownership bổ sung

`server/src/types.py` thêm mutable `RuntimeState` dataclass: `guard:threading.RLock`, `email_locks:dict[str,threading.RLock]`, `rate_events:dict[tuple[str,str],deque[float]]`, `cooldown_until:dict[str,float]`, `replay_entries:dict[tuple[str,str],float]`, `http_slots:threading.BoundedSemaphore`. Factory `create_runtime_state(settings:Settings)->RuntimeState` tạo map rỗng, guard RLock, http_slots=BoundedSemaphore(64). Dependencies frozen bổ sung field `state:RuntimeState`; frozen chỉ chặn gán field dependency, không đóng băng mutable state. Constructor đầy đủ `Dependencies(settings,connect,utc_now,monotonic,mail,keys,state)`.

`main` tạo state đúng một lần cho một process và inject deps vào create_app. HTTP server instance giữ deps; mỗi handler nhận deps từ server instance. Không module-global state, không singleton, không tạo state mới mỗi request. Unit test mỗi test tạo state mới; concurrency test dùng chung cùng deps/state để xác minh serialization. Handler/mail không tự tạo RAM state. `open_request` dùng deps.state.replay_entries; account dùng cùng deps.state counters/email locks; HTTP semaphore dùng deps.state.http_slots và release finally. Mọi signature đã khóa có deps giữ nguyên.

Rate events key=(bucket,key): bucket `otp_email`,`otp_ip`,`login_ip`,`bootstrap_ip`; OTP buckets chứa tất cả register/send attempt được nhận sau cooldown/rate check (SMTP failure vẫn tính); login bucket chỉ failure. Dưới state.guard prune timestamps <= now-window, kiểm limit rồi append atomic. Email lock creation dưới guard, acquire email lock sau release guard; không giữ guard lúc SQL/hash/SMTP hoặc lúc đợi email lock. Email locks giữ tới process exit để không tạo hai lock cho cùng email; skeleton một process, không hỗ trợ nhiều workers. Replay guard atomic prune entry expiry<=now, reject duplicate/full, insert expiry=now+600; không giữ guard trong crypto/DB. Bootstrap sử dụng riêng20/IP/60s, không OTP bucket. Cooldown map normalized email, deadline monotonic như auth.md; check/update cùng guard. Không background cleanup thread.


## Quyết định khóa OTP15 phút (thay mọi mô tả khóa không recovery)

Theo auth.md, migration users thêm registration_locked_until DATETIME6 nullable; verify transaction SELECT users FOR UPDATE cùng email lock; lần5 set counter5/locked_until=utc_now+900s. Khi now<locked_until trả encrypted OTP_LOCKED429+error.retry_after_seconds=ceil delta (>=1). Khi now>=locked_until atomic clear lock/counter rồi xử lý mã hiện hành; nếu đúng nhưng expired trả OTP_EXPIRED, không tự gia hạn generation. Register/send lazy clear khóa hết hạn dưới users row lock; chưa hết hạn vẫn được gửi OTP/overwrite password theo quyết định trước, không mở khóa. verified success clear counter/lock cùng consume. Clock DB value từ deps.utc_now, không RAM/OS app quyết expiry.

Ca bắt buộc: lần5 khóa900s; đúng/sai/expired trong khóa đều OTP_LOCKED (schema valid/account unverified), counter giữ5; ngay900s mở, mã active đúng verify được, mã expired cần resend; sai sau900s counter1; resend/register trước boundary không reset, sau boundary reset0; restart state RAM không mất DB lock; concurrent lần4→5 chỉ một update và mọi verify tiếp theo locked; response retry ceil khi còn0.1s=1, boundary không retry0 OTP_LOCKED.


## close_response lifecycle và timestamp rejection

`close_response` helper nội bộ không cần enforce consumed flag khi bị gọi trực tiếp lần2. HTTP lifecycle gọi một lần/OpenedRequest rồi discard reference trong finally; kiểm bằng spy HTTP lifecycle (success và handler error), không thêm state machine/context registry chỉ để direct-call test. Client native one-use handle vẫn bắt buộc. Timestamp quá skew public INVALID_ENVELOPE như cloud contract, không phát CLOCK_SKEW/detail mới; app invalidate cache và caller thử lại chủ động, không server yêu cầu replay write.
