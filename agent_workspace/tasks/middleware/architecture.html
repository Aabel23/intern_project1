Kiến trúc và luồng xử lý

Bản đồ feature và 21 route hiện có: tài khoản, quyền máy, dashboard, menu/kho và kết nối máy. Mở từng nhóm để xem sơ đồ luồng chi tiết.

Tổng thểTài khoản / OTPPhiênĐăng ký máyChia sẻQuản lý máyMenuKhoCổng máy

Thành phần và ranh giới

Server khởi động bằng import trực tiếp các module trong server/main.py. Route ở server/config/routing.py; cửa vào feature gọi tác vụ nghiệp vụ. Helper chung giữ HTTP, phiên, quyền máy, database và transport; feature giữ validation, SQL và transaction của mình.

Một thao tác điều khiển máy

  1. App gửi thao tác, token và máy mục tiêu tới server.
  2. Tác vụ server kiểm phiên, quyền và dữ liệu; tạo command. Token app dừng tại server.
  3. Máy poll lấy command, thực thi tác vụ và gửi result có định danh lệnh.
  4. Transport chỉ ghép result đúng máy, đúng lệnh với request đang chờ; server trả kết quả về app.

Feature thực tế và luồng nghiệp vụ

21 route của 8 module đã import trong server.main; mỗi nhóm bên dưới có API, dữ liệu vào, nơi lưu, kết quả và các nhánh lỗi/retry. Đây là hiện trạng đọc mã, chưa phải kết quả chạy end-to-end.

Validate và kiểm trùng user; fingerprint request. Tạo/tiếp REGISTRATIONS RAM dưới FLOW_LOCK, băm mật khẩu; gửi OTP ngoài khóa.Cùng ID/cùng dữ liệu tiếp phiên; đổi dữ liệu bị từ chối. Email lỗi/quota có thể làm đăng ký chưa xong; chưa INSERT user ở bước này.

POST /app/xac-minh-otp

Kiểm định dạng, TTL và số lần sai; đánh dấu OTP verified. Đủ data_valid + otp_verified mới INSERT user SQLite.Tạo account hoặc báo OTP sai/hết hạn; trong cùng phiên RAM đã tạo thì trả lại account_created. Crash không có ledger bền giữa commit và cờ RAM.

Đăng ký/OTP giữ state trong RAM, mất khi restart. User đã tạo và phiên đăng nhập nằm trong SQLite; không coi hai nơi này có cùng độ bền.

POST /app/dang-ky-may

6 · Menu trên máy

App giữ snapshot/version; server kiểm quyền rồi relay. Máy quyết định up_to_date, conflict và transaction ghi.

API, dữ liệu, kết quả và các nhánh cần biết

POST /app/nhan-menu

token, machine_id, menu_version (mặc định 0)

Owner/manager; validate CRC32 integer; send nhan_menu không kèm token. Máy đọc SQLite menu, tính version và so bản app.Trùng version → up_to_date; khác → menu mới. Offline503; quyền401/403; máy lỗi hoặc timeout502.
POST /app/cap-nhat-menu

Owner/manager; validate cả gói; relay cap_nhat_menu. Máy so version trước ghi, validate mọi thay đổi và cập nhật SQLite cùng transaction.Version lệch → conflict + menu mới, không ghi. Một thay đổi sai → không ghi cả gói; success trả menu/version mới. Mất response không chứng minh chưa ghi.

Phiên bản CRC32 là phát hiện thay đổi, không phải chữ ký mật mã hay ledger chống thực thi trùng. Token app không nằm trong command gửi máy.

Timeout không xác nhận tác vụ đã hủy

Nếu máy chưa lấy lệnh, timeout có thể xóa lệnh đang chờ. Nếu máy đã lấy, tác vụ có thể đã thực thi dù app không nhận được kết quả. Result tới muộn không được ghép sang request khác; cần đọc lại/đối soát trạng thái trước quyết định gửi lại thao tác ghi.

Hướng bổ sung vào vòng đời request

Đề xuất (chưa triển khai): biên HTTP giới hạn đầu vào → kiểm envelope, clock/epoch, chữ ký và mở HPKE → kiểm phiên/credential → claim attempt bền → quyền nghiệp vụ và chống xử lý trùng theo operation → tác vụ → Seal response đúng một lần. Các đề xuất HTTP hỗ trợ gồm body đọc một lần, response chỉ gửi một lần và giải phóng tài nguyên trên mọi đường ra. Sơ đồ chi tiết ở trang bảo vệ gói tin.

Hiện trạng được hai architect đối chiếu trực tiếp mã nguồn và phản biện qua lại. Lệch hợp đồng C1/C2 đang chờ chốt; chưa sửa code hoặc chạy E2E sản phẩm. Hình thức sơ đồ theo FexMix_Munual.html và FlexMix_System_Manual.html; chưa có PDF mẫu phase-00.pdf để đối chiếu.
